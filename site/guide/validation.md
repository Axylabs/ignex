# Validation & OpenAPI

Declare a schema, get three things at once:

1. **Validation** — invalid input is rejected with a `422` and per-field
   errors before your handler runs.
2. **Types** — `ctx.params`, `ctx.query`, `ctx.body` become fully typed.
3. **OpenAPI** — the schema flows into the generated `openapi.json`, so the
   docs can never disagree with the code.

Schemas are [TypeBox](https://github.com/sinclairzx81/typebox) objects — and
any [Standard Schema](https://standardschema.dev) provider works too (zod,
valibot), with TypeBox unlocking schema-first codegen.

```ts
// src/routes/products/[id].get.ts → GET /products/:id
import { get } from "@ignex/core/http";
import { Type } from "typebox";

export default get(
  (ctx) => ctx.json({ id: ctx.params.id }),
  {
    params: Type.Object({ id: Type.String() }),
    response: { 200: Type.Object({ id: Type.String(), name: Type.String() }) },
  },
);
```

## The schema slots

The second argument to the route helper accepts one schema per request part:

| Slot | Validates | Typing |
| --- | --- | --- |
| `params` | path parameters (`:id`) | `ctx.params` |
| `query` | the query string | `ctx.query` (a grouped record — `{ a: "1", b: ["1","2"] }`) |
| `body` | JSON / form bodies | `ctx.body.json()` result |
| `headers` | request headers | header access |
| `response` | nothing (documented + serialized per status) | return type |

At build time each schema is precompiled into a standalone Ajv validator —
your handler only ever runs on input that already passed.

## Try it: `query` with defaults

```ts
// src/routes/products/index.get.ts → GET /products
import { get } from "@ignex/core/http";
import { Type } from "typebox";

const query = Type.Object({
  page: Type.Optional(Type.Integer({ minimum: 1, default: 1 })),
  pageSize: Type.Optional(Type.Integer({ minimum: 1, maximum: 100, default: 20 })),
});

export default get(
  (ctx) => ctx.json({ page: ctx.query.page, pageSize: ctx.query.pageSize }),
  { query, response: { 200: Type.Object({ page: Type.Number(), pageSize: Type.Number() }) } },
);
```

`GET /products?page=abc` → `422 VALIDATION_ERROR` naming the offending
field. `GET /products` → defaults filled. Your handler never sees raw
strings.

::: tip List endpoints, less boilerplate
List/detail routes repeat the same three shapes. Import them instead:
`Uuid` for params, `pageSchema(Item)` for paginated responses,
`readPagination(ctx)` for reading `?page=&pageSize=`, and
`pageResponse(rows, page, total)` to build the envelope. See the
[Cookbook](./cookbook#the-three-things-every-list-detail-route-repeats).
:::

## FormRequest-style validation (`defineRequest`)

When a request contract is reused across routes — or needs an authorization
gate — bundle the schema, its request part, and the gate into one object
(the Laravel FormRequest pattern):

```ts
// src/requests/create-user.ts
import { defineRequest } from "@ignex/core";
import { Type } from "typebox";

export const CreateUser = defineRequest({
  part: "body", // body | query | params | headers
  schema: Type.Object({
    email: Type.String({ format: "email" }),
    role: Type.Optional(Type.Union([Type.Literal("admin"), Type.Literal("user")])),
  }),
  // optional: 403 when false (runs before validation)
  authorize: (ctx) => ctx.state.user?.role === "admin",
});
```

```ts
// in a route
export default post(async (ctx) => {
  const input = await CreateUser.validate(ctx); // 422 with per-field errors
  return ctx.json(input, { status: 201 });
});
```

## The OpenAPI document

Every schema you declare flows into the compiler's `openapi.json` — real
types, real constraints, grouped into tags by your `routes/` folder layout
(`/api/orders/*` → an `orders` tag). Serve it with the `openapi()` plugin:

```ts
// src/app.config.ts
import { openapi } from "@ignex/core";

export const plugins = [
  // ...
  openapi({ documentation: { title: "my-api", version: "0.1.0" } }),
];
```

- `GET /openapi` — interactive docs UI (Scalar by default, Swagger UI with
  `provider: "swagger-ui"`).
- `GET /openapi.json` — the OpenAPI 3.1 document itself.

Per-route metadata (summary, tags, hide) goes in the schema object via
`detail` — or `export const config = { detail: … }` in AOT apps:

```ts
export default get(handler, {
  params,
  detail: { summary: "List orders", tags: ["orders"] },
});
```

The document is generated by the compiler in AOT apps and by the router at
request time in interpreted apps — either way it's derived, never
hand-written. See [errors.md next](./errors) for how failed validation
reaches the client.

## What invalid input looks like

```json
{
  "error": "Validation failed",
  "status": 422,
  "code": "VALIDATION_ERROR",
  "details": {
    "fieldErrors": { "email": ["format must match format \"email\""] }
  }
}
```

Field-scoped, stable, and safe to show to a form. 4xx responses are never
logged as incidents — they're the caller's fault, not yours.
